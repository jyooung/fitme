# FitMe

LLM 임베딩과 벡터 검색으로 구직자와 채용 공고를 의미 기반으로 연결하는 채용·광고 플랫폼입니다.
이력서·공고를 같은 구조로 요약해 매칭 정확도를 높이고, 기업에게는 매칭 적합도와 입찰가를 함께 반영한 광고를 제공합니다.

- 기간: 2026.01 ~ 2026.02
- 인원: 6인 팀 프로젝트
- 기술 스택: Spring Boot, FastAPI, LangChain, PostgreSQL(pgvector), Redis, OpenAI, Docker, AWS(ECS Fargate), GitHub Actions

<br>

## 개인 담당 부분

**AI 매칭 엔진(AI Worker)과 광고 서빙·과금 구조**를 맡았습니다.
- 내 커밋 모아 보기: https://github.com/jyooung/fitme/commits/main/?author=jyooung

### 1. 이력서·공고 요약과 임베딩 (FastAPI · LangChain)
- **PDF 이력서 처리:** 텍스트가 있는 PDF는 pdfplumber로 바로 읽고, 이미지형 PDF는 Tesseract OCR로 전환합니다. 반복되는 머리말·꼬리말과 쪽 번호를 지우고, 개인정보는 마스킹합니다.
- **같은 구조로 정규화:** 서술형 이력서와 개조식 공고는 표현 방식이 달라 유사도가 낮게 나왔습니다. 공고는 "주요 업무", "자격 요건"만 남기고, 이력서와 공고를 같은 개조식 구조로 맞췄습니다.
- **임베딩 형식 실험:** 서술형 요약과 개조식 키워드를 비교했고, 공고는 LLM 요약(0.7424)보다 규칙 기반 정리(0.7870)가 유사도가 더 높게 나와 규칙 기반을 택했습니다.
- **할루시네이션 방지:** 요약 결과를 LLM이 다시 채점해 4점 미만이면 최대 2번 다시 생성합니다. 팀 프로젝트 경험이 개인 성과로 부풀려지지 않도록 기여도 검증 규칙도 넣었습니다. 채점 결과는 CSV로 남기고, LangSmith로 요청을 추적했습니다.
- **배치 처리:** 임베딩이 비어 있는 이력서·공고를 모아 한 번에 요약·임베딩하는 백필 스크립트를 만들었습니다.

### 2. 매칭 검색 (Spring Boot · pgvector)
- **2단계 매칭:** pgvector HNSW 인덱스로 후보를 먼저 빠르게 뽑고(Recall), 애플리케이션에서 기술 스택 50% · 벡터 유사도 30% · 경력 적합도 20%로 다시 정렬합니다(Re-rank).
- **AI Worker 호출 상태 관리:** 요약 요청을 비동기로 보내고, 상태(PENDING → PROCESSING → FAILED)를 별도 트랜잭션으로 저장해 실패한 작업이 처리 중으로 남지 않게 했습니다.

### 3. 광고 서빙과 클릭 과금 (Redis)
- **광고 노출:** 비로그인 사용자에게는 입찰가 순, 로그인 사용자에게는 이력서 유사도와 입찰가를 합산한 순서로 광고를 보여 줍니다.
- **V1 → V2 → V3 구조 비교:** RDB 단독, Redis 우선, Recall–Guard–Re-rank 하이브리드 세 가지를 만들어 nGrinder로 비교했습니다.
  - Recall: 벡터 인덱스로 유사 공고 후보 추출
  - Guard: Redis에서 예산이 남은 광고인지 확인
  - Re-rank: 유사도 0.7 + 입찰가 0.3 가중 합산
- **조회 성능:** 광고 조회 쿼리가 인덱스를 타지 않아 TPS가 낮았습니다. 유사도로 상위 200개를 먼저 자른 뒤 입찰가를 계산하도록 쿼리를 바꿨습니다.
- **클릭 과금:** Redis Lua 스크립트로 잔액 차감과 활성 광고 목록 제거를 한 번에 처리해, 예산이 0인 광고가 계속 클릭되지 않게 했습니다. 같은 사용자·광고의 클릭은 10분 동안 한 번만 과금합니다.
- **예산 예약·정산:** 하루치 광고 예산을 지갑에서 미리 예약하고, 실제 사용분은 정산, 남은 예약금은 환불합니다. 크레딧은 먼저 충전한 것부터 차감합니다.
- **트랜잭션 분리:** 예산이 부족할 때 광고 상태 변경까지 함께 롤백되던 문제를 트랜잭션을 나눠 해결했습니다.
- 그 밖에 광고 노출 추적, 공고 삭제 시 캠페인 함께 삭제, 기업용 광고 성과 대시보드 연동
